= Try it: the console
:description: S9 as numbered steps: one origin on 8090, sign-in through identity, and the monthly chart embedded for the caller's tenant.

The console is one origin, `http://localhost:8090`. nginx sends `/identity` to identity and `/api` to the edge. The report page asks identity for a guest token and opens the monthly dashboard in an iframe. The figure is the one already on xref:try-superset.adoc#chart[the Superset page]: `ff-eu-freight`, November 2026, 7409. The same origin then received a pallet, delivered the shipment that carried it, and planned a route.

The answers shown are from the first run, on 2026-11-22. The console was synced to `394f8b0`. Superset was synced to `dc56530`, which is the commit that allows this origin to embed the dashboard.

[[up]]
== 1. The console is up

The image is not in GHCR. It is built from `shared/console` and imported into the cluster as `ff-console:local`. `ff-root` then creates the Application. The workload is synced by hand.

[source,bash]
----
cd /mnt/d/dev/workspace/ff-logistic/shared/console
docker build -t ff-console:local .
k3d image import ff-console:local -c ff-logistic
argocd app sync console && argocd app wait console --health --timeout 180
curl -s -o /dev/null -w "%{http_code}\n" localhost:8090/
----

✅ Synced to `394f8b0`, Healthy, and the host port answers:

----
200
----

[[signin]]
== 2. Sign in through identity

Open `http://localhost:8090`. The user on this run was `nexus.planner`, password `fflogistics2026`, tenant `ff-eu-freight`. The browser posts `/identity/sessions`. nginx strips the prefix, so identity sees `/sessions`.

The same user opens Depo, Sevkiyat, Rota and Rapor: the token carries `WAREHOUSE_OPERATOR`, `LOGISTICS_PLANNER`, `TENANT_ADMIN` and `REPORT_VIEWER`. Rapor follows `LOGISTICS_PLANNER`, because that is who can ask identity for a guest token.

[[chart]]

Superset checks the console's origin. `dc56530` sets that list to `http://localhost:8090` and `http://localhost:5173`.

✅ The frame title was `Deliveries per month (ff-eu-freight)`. The bar is November 2026, the 7409 from xref:try-superset.adoc#chart[step 3 of the Superset page].

The defaults were `Cologne Eifeltor Terminal` and `Trieste`, and the edge refused them. This run set the leg to `Cologne Eifeltor` and `Istanbul Hadimkoy`, rail, 1050 km, 18000 kg, DAP, equipment `CSQU3054383`, destination GLN `8690001000011`.

✅ `SHP-17418` planned. *Teslim al*, *Yola çık*, then *Teslim et* with `Dock 2, A. Yilmaz`. The row ended `Teslim edildi`. CO₂e saved 756 kg, 64.5 percent.

== 6. A route, then the two documents

Rota. Territory `IST-EU` was already there. *Sırala* used plate `34 FF 0418`, depot 41.10, 28.65, and the two stops on the form, `IST-ESN` and `IST-KDK`.

✅ `RTE-5008`: 47.7 km, 102 minutes, 600 kg, 17.1 percent full. Esenyurt first (9.9 km, arrival 15 minutes), Kadikoy second (37.9 km, arrival 87 minutes). *Durağı tamamla* on `IST-ESN` with `Dock 2, Route Driver` left that stop `COMPLETED`.

image::console/routing-simulation.png[Console Rota page showing territory IST-EU, route plan on an OpenStreetMap Leaflet canvas, and live stop simulation]

The file buttons ask the edge for a link and then talk to RustFS at `localhost:9000`. The bucket `ff-documents` allows origin `http://localhost:8090` (and `http://localhost:5173`) for `GET`, `PUT` and `HEAD`. Before that rule the page said `Depolama sunucusuna ulaşılamadı`: the preflight came back without `access-control-allow-origin`.

✅ After the rule, *e-POD yükle* stored `epod.png` at `ff-eu-freight/epod/rte-5008-ist-esn/signature.png`, and *e-POD indir* opened it. On `SHP-17418`, *e-CMR yükle* stored `ecmr.pdf` at `ff-eu-freight/ecmr/shp-17418/ecmr.pdf`, and *e-CMR indir* opened it.

That rule was put on the bucket by hand for this run. From image `2b6cccd` the application writes it when it prepares the bucket. With the rule removed, one upload link brought the preflight back: `access-control-allow-origin: http://localhost:8090`, methods `GET`, `PUT`, `HEAD`. The pod logged `browser origins [http://localhost:8090, http://localhost:5173]`.
