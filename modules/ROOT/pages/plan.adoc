= Plan
:description: The sprints of FF Logistic and where the work stands.
:url-backlog: https://github.com/ffetih/ff-logistic-docs/blob/main/backlog.md

The work goes in sprints. Each sprint is one pull request in every repository it touches and ends with something running on the cluster; each backlog item is one commit. The item-level plan, with what proves each item done, is the {url-backlog}[backlog].

[cols="2,2,4",options="header"]
|===
| Sprint | Repositories | Ends with

| S0 Foundation | all | The platform runs; the base libraries and the identity service build; this hub and its site exist
| S1 Walking skeleton and the switch | shared, modulith, services, runtime | An empty app on each side behind the edge; one commit switches; the same smoke test passes on both
| S2 CI, images and progressive delivery | all | Every repository builds in CI; images on GHCR; canary releases on both sides
| S3 Standards and warehousing | shared, modulith, services | The first area runs on both sides from one core
| S4 Transportation and the flows between areas | shared, modulith, services | One shipment crosses three areas, in-process on one side, over REST and Kafka on the other
| S5 Routing and documents | shared, modulith, services | Route planning, e-CMR and e-POD on both sides
| S6 Events out and analytics | shared, modulith, services | Deliveries reach the analytics database from either side
| S7 The comparison | docs, runtime | Memory, startup, latency, failures and the cost of a change, measured on both sides
| S8 Reporting and Superset | shared, runtime | One tenant's months in Superset. The guest token names the tenant. Dashboards are files
| S9 Console | shared, runtime, docs | One origin on 8090: sign-in, warehouse, shipment, route map, documents, embedded monthly dashboard
| S12 Tracing | shared, modulith, services, runtime, docs | Jaeger on 16686. One trace from the console through the active side and Kafka into the loader
| S13 Reporting and notification | shared, runtime, docs | One `shared/reporting` process (`generation` + `delivery`): in-process HTML→PDF from `tenant_delivery_monthly`, RustFS Claim Check, Kafka `report-ready`, Mailpit/webhook delivery
| S14 Multi-cluster, Workflows and Events | shared, runtime, docs | Workflows and Events on the cluster, a monthly CronWorkflow, a Kafka-started workflow, promotion from a second k3d cluster
| S15–S16 Partner gateways | shared, runtime | S15 Northfield, then S16 Corvane. After S14
|===
