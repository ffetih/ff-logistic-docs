= Try it: routing talks to transportation
:description: Flows 1 and 3 of S5 as numbered steps: a road leg's distance asked of routing, the drill with routing down, and a completed route stop that delivers its shipment.

Two flows join routing and transportation (xref:architecture.adoc#flows[the flows]):

* *Flow 1*, a question: transportation asks routing for a road leg's distance (xref:architecture.adoc#flow-1[on each side]).
* *Flow 3*, an event: a completed route stop delivers the shipment it carried (xref:architecture.adoc#flow-3[on each side]), and flow 2 can follow.

The steps run on the services side; the answers shown are from the first run, on 2026-11-20 and 21. They use the territory `IST-EU` of xref:try-route.adoc[Try it: a route].

[[setup]]
== 1. A token, and a road leg by its ends

[source,bash]
----
E=localhost:8081
TOKEN=$(curl -s -H 'Content-Type: application/json' \
  -d '{"username":"nexus.planner","password":"fflogistics2026"}' localhost:8085/sessions | jq -r .accessToken)
H=(-H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json')
ROAD='{"consignorName":"FF Hadimkoy","consigneeName":"Esenyurt Depot Shop","equipmentCode":"CSQU3054383",
 "sscc":"106141411234567897","incoterm":"DAP","origin":"Hadimkoy Hub","destination":"Esenyurt","grossWeightKg":800,
 "legs":[{"mode":"ROAD","origin":"Hadimkoy Hub","destination":"Esenyurt","originLatitude":41.10,"originLongitude":28.65,
 "destinationLatitude":41.03,"destinationLongitude":28.67,"carrierReference":"TR-34-FF-0417"}]}'
plan() { curl -s -w "\n%{http_code} %{time_total}s\n" "${H[@]}" $E/api/v1/tms/shipments -d "$ROAD" \
  | { read -r body; read -r code; echo "$body" | jq '{shipmentNumber, leg: .legs[0] | {distanceKm, distanceSource}, detail}'; echo "$code"; }; }
----

`ROAD` and `plan` live in this terminal only: in another one, `$ROAD` is empty, and the request is refused with `400` before anyone is asked.

[[flow-1]]
== 2. Flow 1: the distance from routing

[source,bash]
----
plan
----

✅ The leg's distance came from routing:

----
{"shipmentNumber": "SHP-10010", "leg": {"distanceKm": 9.87, "distanceSource": "ROUTING"}, "detail": null}
201 0.323629s
----

With the straight-line road matrix (the cluster's default), routing's answer and the estimate are the same 9.87 km; only `distanceSource` tells them apart.

[[flow-1-drill]]
== 3. Drill: routing is down

[source,bash]
----
kubectl -n ff-logistics scale rollout routing --replicas=0
kubectl -n ff-logistics wait --for=delete pod -l app.kubernetes.io/name=routing --timeout=90s
plan
kubectl -n ff-logistics logs -l app.kubernetes.io/name=transportation --since=2m --tail=-1 | grep -m1 "Routing did not answer" | cut -c1-250
----

✅ The shipment is still planned, with the estimate, after the connect timeout:

----
{"shipmentNumber": "SHP-10009", "leg": {"distanceKm": 9.87, "distanceSource": "ESTIMATE"}, "detail": null}
201 1.032739s
WARN … ShipmentService : Routing did not answer for leg 1 (org.springframework.web.client.ResourceAccessException: I/O error on GET request for "http://routing…
----

With no routing pod, the connection was not refused: nothing answered at all, and the 1 s connect timeout ended the wait. Without it, the planner would have waited for the operating system's own timeout, which can be minutes.

[source,bash]
----
kubectl -n ff-logistics scale rollout routing --replicas=2
kubectl -n ff-logistics wait --for=condition=Ready pod -l app.kubernetes.io/name=routing --timeout=120s
----

[[flow-1-lesson]]
=== What the first run found

The very first `plan` after S05-03 answered `ESTIMATE`, with routing up. Transportation's log said why: routing had answered `404 Not Found`. The endpoint routing serves, `/api/v1/geo/distance`, is in shared's routing core; the routing service's own folder had not changed, so CI had not rebuilt its image (xref:delivery.adoc[an image is rebuilt when its folder changes]). The fix: `gh workflow run ci.yml` in the services repository builds every image, then `argocd app sync routing`.

[cols="1,2,1,1,3",options="header"]
|===
| Shipment | Situation | Source | Time | What it showed

| SHP-10008 | routing up, its old image | `ESTIMATE` | 0.40 s | a change in a core means a forced build of the services that use it
| SHP-10009 | routing scaled to 0 | `ESTIMATE` | 1.03 s | the connect timeout bounds the wait; the shipment is planned anyway
| SHP-10010 | routing up, its new image | `ROUTING` | 0.32 s | flow 1 as designed
|===

[[flow-3]]
== 4. Flow 3: a completed stop delivers its shipment

A shipment to the Esenyurt shop, and a route whose stop carries it (`shipmentNumber`):

[source,bash]
----
SHP=$(curl -s "${H[@]}" $E/api/v1/tms/shipments -d "$ROAD"); SID=$(echo "$SHP" | jq -r .id)
SNO=$(echo "$SHP" | jq -r .shipmentNumber); echo "$SNO $(echo "$SHP" | jq -r .status)"
RTE=$(curl -s "${H[@]}" $E/api/v1/geo/routes -d '{"territoryCode":"IST-EU","vehiclePlate":"34 FF 0417",
  "depotLatitude":41.10,"depotLongitude":28.65,"vehicleCapacityKg":3500,"averageSpeedKmh":40,"stops":[
  {"stopCode":"IST-ESN","customerName":"Esenyurt Depot Shop","latitude":41.03,"longitude":28.67,
   "demandWeightKg":800,"serviceMinutes":15,"shipmentNumber":"'$SNO'"}]}')
RID=$(echo "$RTE" | jq -r .id); echo "$RTE" | jq '{routeNumber, stop: .stops[0] | {stopCode, shipmentNumber, status}}'
----

The driver hands over the goods; the stop is completed:

[source,bash]
----
curl -s "${H[@]}" $E/api/v1/geo/routes/$RID/stops/IST-ESN/completion -d '{"receivedBy":"Ayse Demir"}' \
  | jq '.stops[0] | {stopCode, status, receivedBy, completedAt}'
sleep 2; curl -s "${H[@]}" $E/api/v1/tms/shipments/$SID | jq '{shipmentNumber, status, receivedBy, deliveredAt}'
----

✅ The stop is `COMPLETED`, and a moment later the shipment is `DELIVERED`, received by the same person, at the stop's time.
